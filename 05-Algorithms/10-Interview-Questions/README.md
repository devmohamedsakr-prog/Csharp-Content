# Interview Questions - Algorithms

## Overview
This section contains algorithm problems organized by difficulty level and category. Each represents real interview questions with multiple solution approaches.

## Difficulty Levels

### Easy (Warm-up)
- Basic algorithm implementation
- Single technique application
- Linear data structure operations
- Estimated time: 15-20 minutes

### Medium (Core)
- Combination of 2-3 techniques
- Requires optimal thinking
- More complex edge cases
- Estimated time: 30-45 minutes

### Hard (Expert)
- Multiple algorithm combinations
- Requires deep optimization
- Complex problem analysis
- Estimated time: 45-60+ minutes

## Question Categories

### Sorting Related
- **Easy**: Sort implementation, merge operations
- **Medium**: Sort variations, partial sorting, custom comparators
- **Hard**: Median of two arrays, majority element variations

### Searching Related
- **Easy**: Binary search, simple lookups
- **Medium**: Search in rotated array, search with modifications
- **Hard**: Kth smallest element, skyline problem

### Dynamic Programming Related
- **Easy**: Fibonacci, simple path counting
- **Medium**: Coin change, knapsack variants, LCS
- **Hard**: Word break II, max profit with transactions

### Graph Related
- **Easy**: Simple traversal, connectivity
- **Medium**: Shortest path, cycle detection, topological sort
- **Hard**: Network flow, bipartite matching, strongly connected components

### Tree Related
- **Easy**: Traversals, simple BST operations
- **Medium**: BST validation, LCA, diameter
- **Hard**: Serialize/deserialize, tree reconstruction, complex queries

### String Related
- **Easy**: Palindrome, anagram, reversal
- **Medium**: Pattern matching, substring problems, word break
- **Hard**: Regular expression matching, edit distance variations

### Math Related
- **Easy**: GCD, prime checking, factorial
- **Medium**: Combination/permutation, modular arithmetic
- **Hard**: Large number operations, geometric algorithms

### Recursion/Backtracking
- **Easy**: Simple recursion, factorial, power
- **Medium**: Permutations, combinations, subset generation
- **Hard**: N-Queens, Sudoku solver, word search

## Solution Strategies

### Before Coding
- **Listen**: Understand requirements completely
- **Think**: Consider multiple approaches
- **Clarify**: Ask about constraints and edge cases
- **Plan**: Discuss approach before coding

### While Coding
- **Be Clear**: Write readable code
- **Handle**: All edge cases during implementation
- **Test**: With examples as you code
- **Explain**: Narrate your thought process

### After Coding
- **Trace**: Through simple example
- **Verify**: Edge cases work correctly
- **Analyze**: Time and space complexity
- **Optimize**: If time permits

## Complexity Reminders

### Time Complexity
- O(1): Constant operations
- O(log n): Binary search, tree operations
- O(n): Linear scan, simple loops
- O(n log n): Efficient sorting, tree traversal with processing
- O(n²): Nested loops, bubble sort
- O(n³): Triple nested loops, matrix operations
- O(2^n): Exponential, all subsets without memoization
- O(n!): Factorial, all permutations

### Space Complexity
- O(1): Constant space
- O(log n): Recursion depth, balanced tree height
- O(n): Single array/list storage
- O(n²): Matrix storage
- O(n log n): Divide-and-conquer auxiliary space

## Interview Do's and Don'ts
